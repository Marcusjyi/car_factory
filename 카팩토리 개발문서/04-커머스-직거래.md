## 방향

PG 없이 **직거래** 우선.

| 결제 | 설명 |
|------|------|
| 만나서 결제 (`meet`) | 약속 장소에서 확인 후 현금·현장 송금 |
| 계좌이체 (`transfer`) | 판매자 계좌 입금 |

## 상태 플로우

```text
selling (판매중)
   │ 채팅 합의 → 판매자 「예약중으로 표시」
   ▼
reserved + orders.status=reserved
   │
   ├─ 판매자 「판매완료」 → sold + orders.completed (+ chatOpenUntil)
   └─ 판매자 「예약 취소」 → selling + orders.cancelled
```

## 권한

| 액션 | 판매자 | 구매자 |
|------|--------|--------|
| 예약중으로 표시 | O (채팅에서 buyerUid) | 하위호환 self-reserve 가능하나 UI는 판매자 중심 |
| 예약 취소 | O | X (채팅 요청) |
| 판매완료 | O | X |
| 계좌 등록 (`setTradeTransferInfo`) | O | X |

## 구현 불변조건

1. `orders` 클라이언트 쓰기 금지.
2. 예약 시 상품에 `reservedBuyerUid`, `activeOrderId` 설정.
3. 다른 구매자 채팅방 → 예약 시 `blocked`, 취소 시 복구, 완료 시 비승자 `closed`.
4. 판매완료 후 승자 방만 `chatOpenUntil`(+30일) 동안 메시지 가능.
5. 완료 시 `fulfillmentMethod` 필수. `delivery`면 운송사+송장(≥4자).
6. 장바구니에는 `selling`만. 예약 자동 만료 없음.
7. `/checkout` → `/cart` 리다이렉트 (PG 없음).
8. 예약중 상품: 판매자 단독 판매완료·자유 수정·삭제 차단.
